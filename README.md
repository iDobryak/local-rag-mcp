# Local RAG MCP

## Общее описание проекта

`local-rag-mcp` — это локальный ассистент для вопросов по внутренней базе знаний компании. Проект объединяет RAG-пайплайн (Retrieval-Augmented Generation), локальную LLM через Ollama и MCP-инструменты для доступа к документам, чтобы отвечать на вопросы по корпоративной документации без вынесения данных во внешние облачные сервисы.

Основной сценарий использования:
- загрузить локальные документы компании;
- построить векторный индекс;
- задавать вопросы в CLI;
- получать ответ на основе найденных фрагментов документов;
- при необходимости дополнительно читать или искать документы через MCP-tools.

## Детальное описание проекта

Проект реализован как консольное Python-приложение с точкой входа в `src/main.py`. После запуска ассистент работает в интерактивном режиме: принимает вопрос пользователя, извлекает релевантные фрагменты из локальной базы знаний и передает собранный контекст в локальную языковую модель.

Знания строятся из файлов, лежащих в каталоге документов. В текущей реализации поддерживаются форматы:
- `.txt`
- `.md`
- `.pdf`
- `.docx`

Процесс работы делится на две фазы:

1. Подготовка базы знаний.
   Документы читаются с диска, разбиваются на чанки, переводятся в эмбеддинги и сохраняются в FAISS-индекс вместе с метаданными чанков.

2. Ответ на вопрос.
   Для пользовательского запроса вычисляется эмбеддинг, по FAISS ищутся наиболее похожие фрагменты, затем на основе найденного контекста формируется prompt для Ollama. Дополнительно ассистент может решить, нужно ли вызвать MCP-инструмент для чтения полного документа, списка документов или поиска по именам файлов.

Таким образом, проект решает сразу две задачи:
- семантический поиск по локальному корпусу документов;
- управляемый доступ к документам через стандартизированные MCP-инструменты.

## Архитектура

Архитектура проекта состоит из трех основных слоев.

### 1. CLI и orchestration layer

Файлы:
- `src/main.py`
- `src/assistant.py`

Этот слой отвечает за пользовательский интерфейс и координацию всего пайплайна:
- запуск ассистента в интерактивном режиме;
- переключение в режим построения индекса;
- вызов retrieval;
- принятие решения о необходимости MCP;
- сбор итогового prompt;
- возврат ответа, списка источников и информации об использовании MCP.

### 2. RAG layer

Файлы:
- `src/rag/ingest.py`
- `src/rag/chunk.py`
- `src/rag/embed.py`
- `src/rag/build_index.py`
- `src/rag/query.py`

Этот слой отвечает за обработку и поиск знаний:
- ingestion документов из локальной папки;
- извлечение текста из `txt/md/pdf/docx`;
- разбиение текста на чанки с overlap;
- генерацию эмбеддингов через `sentence-transformers`;
- построение и сохранение FAISS-индекса;
- retrieval top-k релевантных фрагментов;
- формирование prompt для LLM.

### 3. MCP layer

Файлы:
- `src/mcp/server.py`
- `src/mcp/client.py`

Этот слой дает ассистенту доступ к инструментам поверх локальной базы документов:
- `read_document(file_path)` — прочитать конкретный документ;
- `list_documents()` — получить список документов;
- `search_documents(query)` — найти документы по имени файла.

Ассистент поднимает MCP-сервер как дочерний процесс и общается с ним по JSON-RPC через stdio.

### Поток выполнения

1. Пользователь задает вопрос в CLI.
2. `CompanyKBAssistant` вызывает retrieval из `rag.query`.
3. Из FAISS извлекаются наиболее релевантные чанки.
4. LLM отдельно оценивает, нужен ли вызов MCP-инструмента.
5. При необходимости вызывается локальный MCP-сервер.
6. Контекст из RAG и результат MCP объединяются в один prompt.
7. Ollama генерирует финальный ответ.
8. Пользователь получает ответ, источники и сведения об использованном MCP-tool.

## Подход

В основе проекта лежит pragmatic local-first подход.

### Local-first

Все ключевые части работают локально:
- документы находятся на диске;
- эмбеддинги считаются локально;
- индекс хранится локально;
- генерация ответа выполняется через локальную модель Ollama;
- доступ к документам организован через локальный MCP-сервер.

Это снижает риски по приватности и делает решение пригодным для внутренней корпоративной документации.

### RAG вместо прямой генерации

LLM не отвечает “из головы” по документам, а получает извлеченный контекст из базы знаний. Это уменьшает вероятность галлюцинаций и позволяет привязывать ответы к конкретным источникам.

### MCP как дополнительный инструментальный слой

RAG хорошо решает задачу поиска релевантных фрагментов, но не всегда достаточно для доступа к полному документу или навигации по каталогу знаний. MCP закрывает этот пробел и делает систему расширяемой: при необходимости можно добавлять новые tools без переписывания основного ассистента.

### Простота разворачивания

Проект минималистичен по структуре и ориентирован на быстрый локальный запуск:
- Python dependencies устанавливаются из `src/requirements.txt`;
- индекс собирается отдельной командой;
- запуск выполняется через обычный CLI;
- конфигурация сосредоточена в `src/config.py`.

local-rag-mcp/

## Технический стек

### Язык и среда

- Python 3

### Поиск и RAG

- `sentence-transformers` — генерация эмбеддингов
- `FAISS (faiss-cpu)` — векторный поиск по чанкам
- `tiktoken` — токенизация и чанкирование
- `numpy` — работа с векторами

### LLM

- `Ollama` — локальный inference server
- модель по умолчанию: `qwen3:0.6b`

### Работа с документами

- `pypdf` — чтение PDF
- `python-docx` — чтение DOCX

### MCP

- `fastmcp` — реализация MCP-сервера
- собственный JSON-RPC клиент на `subprocess` + `stdio`

### CLI и UX

- стандартный CLI через `input/print`
- `rich` — улучшенный вывод markdown-ответов
- `requests` / `ollama` — взаимодействие с локальной моделью

## Конфигурация

Основные настройки находятся в `src/config.py`:
- `DOCUMENTS_DIR` — каталог с документами;
- `CHUNK_SIZE` и `CHUNK_OVERLAP` — параметры чанкирования;
- `EMBEDDING_MODEL` — модель эмбеддингов;
- `FAISS_INDEX_PATH` и `CHUNKS_PATH` — пути для индекса и чанков;
- `OLLAMA_URL` и `OLLAMA_MODEL` — настройки локальной LLM;
- `TOP_K` — число извлекаемых фрагментов.

Текущее значение `DOCUMENTS_DIR` — `./docs`, поэтому проект ожидает документы в каталоге `src/docs`, если запускать его из `src`, как предполагается текущими инструкциями.

## Как запускать

```bash
cd src
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python main.py build-index
python main.py
```

## Что важно знать о текущей реализации

- Проект ориентирован на локальный запуск и разработку, а не на production deployment.
- Ответы формируются по top-k retrieval без отдельного reranker-слоя.
- MCP используется как дополнительный источник данных, а не как обязательная часть каждого запроса.
- Индекс может быть автоматически перестроен, если отсутствуют `index.faiss` или `chunks.pkl`.
